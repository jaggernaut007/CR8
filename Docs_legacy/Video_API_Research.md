# CR8 Video API Research & Architecture

**Last Updated**: 2026-02-20

---

## The Requirement

Produce 2-minute educational videos programmatically where an AI avatar presents over auto-progressing slides extracted from the original curriculum materials (PDF/PPTX). The script is generated by the existing LangGraph multi-agent pipeline. Everything must be API-driven — no manual UI interaction.

---

## Current Implementation (What Exists)

The pipeline has a working Script Agent and Video Agent:

`video_builder.py` integrates with HeyGen's `/v2/video/generate` endpoint. It splits scripts into scenes (5,000 char limit per scene), submits each scene with a full-screen avatar on a white background (`#FFFFFF`), polls for completion, and downloads the MP4. Videos are generated in parallel (ThreadPoolExecutor, max 2 workers). The `MODULE_TO_SCRIPT` prompt in `video.py` converts learning modules into 300-750 word spoken narratives (2-5 min at natural pace).

Current gaps: no slide image export from PPTX/PDF, no slide-to-scene mapping, no custom backgrounds per scene, no `[SLIDE N]` markers in scripts, and the HeyGen payload hardcodes a white colour background.

---

## Video API Evaluation

Ten platforms were evaluated for the specific capability of programmatic avatar + slide composition via REST API.

### Tier 1 — Native Slide-to-Video APIs (Recommended)

**Elai.io** — Best fit for the CR8 use case. Their API has a dedicated PPTX-to-video endpoint (`POST /api/v1/videos/from-presentation`) that accepts a multipart PPTX upload, converts each slide into a video scene background, and overlays an avatar narrator. Slides auto-progress as the avatar speaks. Available on all paid plans including the $23/mo Basic tier (15 min/mo, ~$1.53/min) and the $59/mo Advanced tier (100 min/mo, ~$0.59/min). The API also supports adding custom scripts per slide rather than relying on speaker notes.

**Synthesia** — Enterprise-grade with native PowerPoint integration. Supports importing up to 150 slides (1GB), scene-level avatar positioning (full screen, corner overlay, or hidden), and auto-progression. API available on Creator plan ($29/mo) and above. Best for institutional deployments where SOC 2 compliance matters. Cost per minute is higher than Elai at scale but includes SCORM export for LMS integration.

**DeepBrain AI Studios** — REST API with presentation-to-video conversion (`POST /odin/v3/tools/video-generator` and `/odin/v3/automation/topic_to_video`). Supports PowerPoint/PDF upload and auto-generates scenes with AI presenter. Solid alternative if Elai.io or Synthesia pricing doesn't fit.

### Tier 2 — Scene-Based APIs (Require Custom Integration)

**HeyGen** (current integration) — The `/v2/video/generate` API supports scene-based videos where each scene can have a different background. The background object accepts `type: "image"` with a URL or `image_asset_id`. This means the existing integration can be extended: export slides as PNG images, host them (or upload as HeyGen assets), and set each slide image as the scene background with the avatar overlaid. The avatar can be scaled down (e.g., `scale: 0.3`) and positioned to appear as a picture-in-picture overlay on the slide. Cost: ~$0.20/min via API credits. This is the lowest-effort upgrade path since the integration already exists.

**D-ID** — Creative Reality API supports custom backgrounds per video but has no native multi-scene or slide progression support. Each video is a single talking-head clip. Would require generating one clip per slide and stitching externally with ffmpeg. API starts at $5.99/mo (Lite, 10 min). Not recommended for this use case due to the stitching overhead.

**Colossyan** — Template-based API with dynamic variable replacement. Can define multi-scene templates, but not specifically optimized for variable-length slide presentations. Enterprise pricing.

### Tier 3 — Limited API / Not Recommended

**KreadoAI** — Has a PPT-to-avatar feature in the UI ($6/mo, ~$0.40/min) but API documentation is immature. Not reliably automatable for a production pipeline.

**Vidnoz** — Open API available with avatar templates but no documented PPTX import via API. Web UI has one-click PPT conversion but no programmatic equivalent.

**Tavus** — Optimized for conversational AI and personalized outreach videos, not presentation-style content. $39/mo starter, $0.37/min overage.

**Hour One** — Studio API exists but documentation is limited. Not specifically designed for slide-based presentations.

### Tier 4 — Open Source / Self-Hosted

**SadTalker + ffmpeg** — Generate a talking head from a single image + TTS audio, then composite over slide images using ffmpeg. Free (infrastructure costs only). Requires significant custom integration: TTS generation (gTTS/Azure), avatar rendering, slide timing calculation, and ffmpeg compositing. Latency: 30s-2min per video on GPU. Quality: 720p, good facial animation but less polished than commercial APIs.

**Wav2Lip + ffmpeg** — Lip-sync only (requires source video footage). Better lip accuracy than SadTalker but less expression variety.

**MuseTalk** — Modern architecture, near real-time performance. Best open-source option for quality but requires GPU infrastructure.

## Recommended Approach

### Primary Path: Extend HeyGen Integration (Lowest Effort)

The existing `video_builder.py` already handles scene-based video generation. The upgrade involves:

1. Export slides as PNG images from the original PPTX/PDF files (extend `file_parser.py` with `export_slides_as_images()`)
2. Modify the `MODULE_TO_SCRIPT` prompt to generate scripts with `[SLIDE N]` transition markers
3. Parse script markers to split the script into per-slide segments
4. Upload slide PNGs as HeyGen assets or host on GCS and reference by URL
5. Set each scene's background to the corresponding slide image instead of `#FFFFFF`
6. Scale the avatar down (e.g., `scale: 0.3`) and position in the bottom-right corner

This changes approximately 4 files: `file_parser.py` (add image export), `video.py` (update prompt with slide markers), `video_builder.py` (add slide backgrounds to scenes), and `agent_generate.py` (wire slide images into the video build step).

### Secondary Path: Elai.io API (Simplest for Native PPTX Support)

If the HeyGen scene-background approach proves limited (e.g., avatar positioning control is insufficient), migrate to Elai.io's dedicated PPTX-to-video endpoint. This would mean replacing `video_builder.py` with an Elai.io client that uploads the PPTX directly alongside the generated script. The trade-off is higher per-minute cost ($0.59 vs $0.20) but simpler integration with guaranteed slide progression.

### Fallback Path: Post-Processing with ffmpeg/MoviePy

If neither API approach gives sufficient control over layout, generate the avatar video via HeyGen (as-is) and composite the slides in post-processing:

```
Avatar MP4 (HeyGen) + Slide PNGs (exported) → ffmpeg composite → Final MP4
```

This gives full control over avatar size, position, slide transitions, and timing but adds compute overhead and complexity. Example compositing with MoviePy:

```python
from moviepy.editor import VideoFileClip, ImageClip, CompositeVideoClip

avatar = VideoFileClip("avatar_narration.mp4")
slide = ImageClip("slide_01.png").set_duration(15).resize(avatar.size)

# Avatar as picture-in-picture over slide
avatar_pip = avatar.resize(0.3).set_position(("right", "bottom"))
scene = CompositeVideoClip([slide, avatar_pip]).set_audio(avatar.audio)
```

## Implementation Plan (Phase 1 Priority)

**Step 1 — Slide Image Export** (file_parser.py): Add `export_slides_as_images()` function. For PPTX: use python-pptx to render slides via LibreOffice headless conversion (`soffice --headless --convert-to png`). For PDF: use PyMuPDF (`fitz`) to render pages as images at 1920x1080.

**Step 2 — Script-Slide Mapping** (video.py): Update `MODULE_TO_SCRIPT` prompt to include slide count and require `[SLIDE N]` markers in the generated script. The LLM maps script content to the specific slides being discussed.

**Step 3 — Scene Background Integration** (video_builder.py): Replace the hardcoded white background with slide image references. Modify `_split_into_scenes()` to split on `[SLIDE N]` markers instead of character count. Each scene gets: avatar (scaled to 30%, positioned bottom-right) + slide image background.

**Step 4 — Pipeline Wiring** (agent_generate.py + state.py): Pass original file paths through the pipeline state. After script generation, extract slide images and create the slide-to-script mapping. Pass both to `build_videos()`.

**Step 5 — Configuration** (config.py): Add settings for avatar scale/position, slide export resolution, background type preference, and fallback API selection.

**Step 6 — Testing**: Add tests for slide export (verify image count matches slide count), script marker parsing, scene-slide alignment, and end-to-end video generation with slides.

## Architecture Gap Analysis (Current vs. Target)

| Component | Current State | Needed for Slides-in-Video | Gap Size |
|-----------|---------------|--------------------------|----------|
| Video Script Generation | Text-only narrative | Needs `[SLIDE N]` transition markers | Medium |
| Slide Extraction | Text extraction only | Full image export + metadata | Large |
| Video Composition | Avatar + white background | Avatar + slide image background per scene | Large |
| HeyGen Integration | Scene text input only | Scene text + background image URL | Medium |
| Script-to-Slide Mapping | None | LLM-driven alignment with markers | Large |
